# CoreGeek 基础防守策略

在 Competition 原始 Demo 上修改，原始仓库：https://github.com/Tymonxiong/Competition ，基线提交 `7e62942`。

## 运行

Python 3.11+，仅使用标准库。启动 HTTP 服务，监听 `0.0.0.0`：

```bash
bash Demo/CoreGeek/run.sh 8081
```

Windows 或无 Bash 环境：

```text
python -B Demo/CoreGeek/main3.py 8081
```

向该端口 POST 比赛 Request JSON，返回 `roleCommandMap`、`prompt` 和 `executeCmd`。
后两项在基础版恒为空。无需安装本仓库对战平台的依赖，也不调用外部 LLM。

## 基础版策略

- 基地为 2×2，接口 `pos` 为左上角，覆盖 `(x,y)`、`(x+1,y)`、`(x,y-1)`、`(x+1,y-1)`。
- 武器只建在距基地占地切比雪夫距离为1的12格；围墙只建在距离为2的20格。
- 开局三座武器：两座火箭、一座电磁炮，共75金币。优先选择工人身边可建位置。若出生位置和障碍允许，第一回合建两座、第二回合补第三座；不会为了保证两回合而发送超距离建造。
- 左侧基地建右半圈10段墙，右侧基地建左半圈10段墙；后半圈保持开放。优先补墙，采石每趟最多3块。
- 工事完成后采矿、批量卖矿、采购升级券。采集按实时价格、去矿路程及估计出售路程评分，买券前保留缺失炮台的重建预算。
- 优先升级火箭；基地不足60%血时优先考虑基地升级，其次普通基地升级、电磁炮升级。采购采用共享预算，持券工人优先送券。
- 回防采用障碍地图上的路径距离，预留5回合；出发前检查工作地点返程成本。矿点到小贩的收益估算仍使用切比雪夫距离。
- 角色与炮台枚举分配，优先减少走路；死亡或炮台被毁后按现状重新分配。
- 火箭搜索机器人周围的合法落点，考虑中心20、邻格10伤害，支持空格爆炸和同位置多弹叠加；多炮维护预计剩余血量以减少过量伤害。
- 电磁炮按沿线机器人估算穿透能量消耗。机器人目标阵营、威胁及血量影响火力选择。
- 寻路包含可见敌军、己方存活单位、中立区域、机器人；同回合预留移动和建造位置，预算和三座武器上限统一管理。

## 验证

```text
python -B -m unittest discover -s Demo/CoreGeek/tests -v
```

测试涵盖开局两回合建齐、金币共享、数量上限、左右建造圈、敌方阻挡、日落回防、AOE空格落点、多弹叠加、冷却、操作者互斥、出售和升级、电磁能量、HTTP响应。
另有70回合简化白天场景，验证三炮、迎敌半圈墙和回防。
该场景没有模拟机器人、矿点枯竭、动态新闻或战斗，不能作为实际首夜生存保证。

## 已知限制和后续工作

- 尚未运行官方判题器，首夜胜率、不同种子的经济收益和完整10天生存待验证。
- 本仓库模拟器 `sim/engine/state.py` 的 `cells_of`、`zone_distance` 目前使用 `y+1` 展开基地，与接口左上角定义不同。Demo 使用 `y-1`，直接对局前需要先统一模拟器规则；本次未改模拟器。
- 电磁弹道采用线段与格子相交近似，边界命中和同时伤害的细节仍需与判题器核对。
- 前方半圈和两火箭一电磁为固定基础配置，不会学习机器人出生方向。
- 本版未接任务、宝藏、新闻语义推理、召唤令、炸弹采购、墙体修复或升级；暂不持久记录动作失败。矿点存在但因新闻停采时，可能重复采集失败。
- 背包内有 Medicine 时可在火箭冷却期间回血；当前没有主动购买药剂策略。
- 没有对未知隐身敌军或机器人下一步移动做预测，移动仍可能发生碰撞。
