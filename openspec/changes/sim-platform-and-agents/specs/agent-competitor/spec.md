# agent-competitor 我方 agent 规格

## Purpose

我方参赛 agent：以 OpponentModel 每回合收集对手确定性动作、以教义×旋钮参数化策略引擎执行日常调度、以每日 3 次 LLM 预算在日界做策略分析——实现"代码执行策略、LLM 分析与调参"的分工。

## ADDED Requirements

### Requirement: OpponentModel 对手动作收集
我方 agent SHALL 在每个回合结束后，从全局信息通道（敌方基地/围墙全量数据、机器人全量数据、矿价/商店货架）与视野内敌情，以逐回合 diff 提取对手全部确定性动作并滚动更新对手画像，至少包括：围墙/建筑的数量-等级-位置变化、武器击杀指纹（机器人血量掉落模式推断武器类型与 DPS）、骚扰检测（超基线波次与 targetTeam 归属）、对手经济与任务活动的推断指标。对手画像 MUST 每回合更新且保留历史时间序列。

#### Scenario: 建墙动作捕获
- **WHEN** 对手在某回合新增 2 座围墙
- **THEN** OpponentModel 记录对手该回合的建墙动作（位置、数量、等级），围墙总数更新

#### Scenario: 武器指纹推断
- **WHEN** 某回合我方视野外一台机器人血量从 60 降至 40（-20 单体）
- **THEN** OpponentModel 更新对手火力画像，推断该伤害来源武器类型（如 L1 火箭）

#### Scenario: 骚扰检测
- **WHEN** 我方夜晚机器人数量超出基础波次且新增机器人 targetTeam 为我方
- **THEN** OpponentModel 记录对手一次召唤令骚扰（可推断档位），并计入骚扰强度时序

### Requirement: 教义×旋钮策略引擎
我方 agent SHALL 以参数化引擎执行日常调度：离散教义层（经济压制/均衡发展/龟缩防御/骚扰进攻/任务冲刺等预设卡）+ 连续旋钮层（骚扰预算比例、围墙密度、武器配比、任务节奏、采集偏好、升级优先级、囤卖时机等）。日常调度（移动/采集/建造/瞄准/交易）MUST 为零 LLM 的确定性计算。当前生效参数 MUST 可在日界原子替换（热插拔），所有旋钮 MUST 有硬性取值域夹紧。

#### Scenario: 零 LLM 日常调度
- **WHEN** 我方 agent 处理一个无任务、无日界的普通回合
- **THEN** response 的 prompt 字段为空，全部指令由确定性引擎生成

#### Scenario: 参数热替换
- **WHEN** 日界分析产出新教义参数（已夹紧）
- **THEN** 当天起策略引擎按新参数执行，无需重启进程

### Requirement: 每日 LLM 策略分析
我方 agent SHALL 在每个游戏日第一回合发起一次合并分析调用（每日 3 次预算的一部分）：输入为一屏仪表盘（OpponentModel 特征摘要、资源/积分/建筑现状、今日新闻、累积传闻）+ 教义索引（仅名称与一句话描述），期望输出为结构化 JSON（选定教义、旋钮微调、异常备注）。LLM 输出 MUST 经 schema 校验与数值夹紧后方可生效；LLM 不可用或输出不合法时 MUST 回退到推荐兜底链（昨日教义 → 全局默认），不得空转。

#### Scenario: 日界分析调用
- **WHEN** 第 4 个游戏日第一回合
- **THEN** prompt 字段携带仪表盘与教义索引发起当日首次 LLM 分析，下一回合读取结果并更新当日参数

#### Scenario: LLM 输出兜底
- **WHEN** llmResp 内容不合法（非约定 JSON 或数值越界）
- **THEN** 丢弃该输出，当日沿用兜底链的教义参数，agent 正常运转

### Requirement: 推理类与宝藏任务求解
我方 agent SHALL 利用新闻推理与宝藏求解能力：官方消息触发囤卖套利时机表；民间传闻逐日积累并收敛宝藏假说，在高信心（地点/祭品/时间三要素齐备）时执行召唤。召唤 MUST 采取高信心出手原则——召唤动作合法即消耗祭品。

#### Scenario: 囤货套利
- **WHEN** 新闻推理出铁明日停采 2 天且当前铁价尚未上涨
- **THEN** 引擎调整当日卖出计划为抛售手中铁（若有），并对停采期间采集偏好降权铁

#### Scenario: 高信心召唤
- **WHEN** 宝藏假说三要素（地点/祭品/时间）已收敛且开拓者在场
- **THEN** agent 规划开拓者购买祭品、抵达地点并在时间窗口内执行 summonTreasure

### Requirement: 出站合规与生存兜底
我方 agent 的全部输出 SHALL 经公共骨架的严格格式校验器后出站（继承 agent-framework 对应要求）；夜间 MUST 保证武器操控角色的火控分配不出现"无角色操控"的浪费回合；任何参数异常 MUST 收敛到保守生存模式（优先基地存活）。

#### Scenario: 夜间火控不空转
- **WHEN** 夜晚有存活机器人进入武器射程
- **THEN** 引擎为每座可用武器分配操控角色与目标，不出现武器闲置而角色游荡的回合

#### Scenario: 保守生存收敛
- **WHEN** 检测到基地血量跌破阈值
- **THEN** 策略收敛为保守模式（修复/升级优先、外出角色回撤）
